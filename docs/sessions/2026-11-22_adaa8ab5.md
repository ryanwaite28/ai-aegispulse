I evaluated the switch with the systems-architect skill, found no architectural risks, so it went through automatically. The gateway is now NestJS on the Fastify adapter at `gateway/nest-http/`, and every document uses that name.

**Why it's safe:** the change only swaps the framework inside the single external gateway. The architecture rules are all untouched: one entrypoint, no database access from the gateway, data ownership, the outbox, the event envelope, token checks on every hop, and the resource budget.

**Guardrails for the real risks:** NestJS brings implementation risks, not architectural ones. I added these rules to the new decision record and enforce them in the docs and review agents:
- **Nothing in the gateway is called a "service".** Nest's convention of `*.service.ts` providers would blur the line with the real service layer. Gateway providers must be typed clients (`*.client.ts`) or mappers only. Controllers call one client method; guards check tokens; pipes validate with Zod; interceptors handle request IDs, timeouts and the error format.
- **The API spec stays hand-written.** I didn't adopt `@nestjs/swagger` generation. `/v1/openapi.json` is served from the hand-written spec in `packages/contracts`, and a contract test keeps the controllers and the spec in sync.
- **Webhook signatures still check raw bytes:** `rawBody: true` is set on the Fastify adapter, so signatures are computed over the exact bytes received.
- **Rate limiting stays in memory:** I chose `@nestjs/throttler` with per-pod memory, so the gateway still talks to no database.
- **Streaming fits the existing pieces:** `@Sse()` returns RxJS observables, which fits your `rxjs-rabbitmq` library.
- **Decorator settings are confined to the gateway:** the two TypeScript flags NestJS needs are enabled only there. Strict mode and the ban on `any` stay everywhere.
- **Memory:** NestJS adds roughly 20–40 MiB, within the existing 384 Mi limit. The Phase 18 soak test will confirm it.

**Scope:** only the external gateway changed. The internal HTTP endpoints of the Node services (ingestion, files, events, orchestrator) stay on plain Fastify, since they aren't gateways and Nest adds nothing there.
