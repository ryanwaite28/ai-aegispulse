The effect is real but narrow. It cuts what Claude has to read; it doesn't cut what Claude has to think or write.

## Why it works where it works

The saving is larger than the per-call estimate suggests. A 20k-token log read on turn 10 of a 60-turn session stays in context and is re-read on every later turn until compaction. Keeping it out saves 20k tokens once per remaining turn, not once. It also pushes back context compaction.

| Use | Real value | Evidence so far |
|---|---|---|
| Long test, integration or compose logs | **High.** Failures buried in thousands of lines, typical of `make test-integration` across pnpm packages | 7B triage gave exact names, `file:line` and errors in about 10 s |
| Finding a section in big docs like PROJECT.md (3,600+ lines) | **High.** Read again in almost every session | Another session already used `summarize-file` (24k chars → 1.6k) |
| Getting oriented in a large diff before review | Medium | Not yet measured |
| Inventories from grep output | Medium | Not yet measured |
| Commit messages | **Low.** Claude already knows what it changed and wouldn't read the whole diff | The "15k tokens kept out" in stats is mostly not a real saving |
| Test skeletons | Low to medium. Saves Claude's writing, but Claude must read and fix the draft | Accurate, but about 95 s per run |

## Why it isn't higher

1. **Comparing against good habits shrinks the win.** Claude already pipes test output through `tail`/`grep`, which avoids most of the bulk. The offload mostly helps when the failure isn't at the tail, or when output is spread across many packages.
2. **Whether it gets used depends on Claude remembering.** Nothing makes the cheap path the default; the skill only triggers if Claude decides to load it.
3. **Verification can cancel the saving.** If Claude reads the source after a summary, the summary was wasted work. The skill says to check narrowly, but that's a habit, not a guarantee.
4. **Latency and memory.** The 14B model takes 1–2 minutes per call. On 24 GB of RAM shared with the full compose stack, it can cause memory pressure.
5. **Quality limits.** The 7B model invented FR ids in commit drafts. Local models are only safe for condensing and drafting, which is how it's set up.
6. **The stats overstate it.** They count every input character as saved, including commit-msg, where Claude would never have read the full input.

## What would raise it to about 8/10

1. **Make the cheap path the default** (biggest gain). Add brief variants of the test targets, such as `make test-unit-brief` and `test-integration-brief`. They would run the suite, save the full log to the scratchpad, and print the exit code plus a local summary, falling back to `tail -60` when Ollama is down. Then the project-manager definition of done would point at those targets, and sessions would save without having to remember the skill.
2. **Count only real savings.** Have `llm-stats` count only tasks where Claude would otherwise have read the input (log, file, diff, inventory), and stop crediting commit-msg.
3. **Move commit-msg back to the fast model, or drop it.** It saves little, and 54 s on the deep model isn't worth it.
4. **Measure it once.** Compare `/cost` or usage across two similar slices, one with offload and one without, instead of relying on the character estimate.
