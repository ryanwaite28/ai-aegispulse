# ADR-0009 — Files stay out of the broker; presigned uploads; pointer-only events

- **Status:** Accepted
- **Date:** 2026-11-22
- **PROJECT.md sections affected:** §2.7, §6.4, §7.3, §7.8
- **Related:** FR-FILE-*, NFR-15

## Context
Large binaries in RabbitMQ hurt memory, throughput, and redelivery. Cloudflare caps proxied bodies at 100 MB.

## Decision
- Clients upload directly to the object store with short-lived presigned PUT URLs (10 min) that sign the content type and length. Single PUTs are capped at 64 MiB, and multipart uploads use 16 MiB parts.
- Object keys are generated by the server (`raw/{tenantId}/{yyyy}/{mm}/{dd}/{fileId}`) and never derived from filenames.
- Events carry `fileId`, `storageKey`, and `sha256` only. Messages are 256 KiB at most.
- The Files Service owns the lifecycle. Doc Extraction reads through Files-issued presigned GETs and doesn't hold bucket-wide credentials.

## Consequences
- An object-store ingress host (`aegispulse-objects.rmwhs.com`) must be public, and it accepts only signed requests.
- Orphaned uploads need sweeping (FR-FILE-10).

## Verification
Upload E2E tests, the orphan flood chaos scenario, and the publisher kit rejecting messages over 256 KiB.
